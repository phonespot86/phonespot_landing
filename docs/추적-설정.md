## Microsoft Clarity (2026-08-10 추가)

프로젝트 ID **`y03pzj9oqr`** · 대시보드 `https://clarity.microsoft.com/projects/view/y03pzj9oqr`

공식 스니펫을 `<head>` 끝(당근 픽셀 블록 바로 뒤)에 그대로 삽입. GTM을 거치지 않는다.
설치 검증 완료 — `l.clarity.ms/collect` 전송 + `_clck`/`_clsk` 쿠키 발급 확인.

**역할 분담**: GA4는 "얼마나·어디서"(정량), Clarity는 "왜"(정성). Clarity를 지표 집계용으로 쓰지 말 것.
GA4에서 이상 신호를 잡고 → Clarity 리플레이로 원인을 확인하는 순서가 기본이다.

**⚠️ 이 페이지 특유의 한계.** Clarity 리플레이는 DOM 변화를 재구성하는 방식이라,
`#vbody`를 transform으로 직접 움직이는 **모바일 가상 스크롤은 리플레이·히트맵이 실제와 어긋날 수 있다.**
스크롤 히트맵의 좌표·도달률을 액면 그대로 믿지 말 것. 판정거림 같은 성능 문제는
리플레이로 판단하지 말고 실기기에서 직접 확인해야 한다.

**그래도 확실히 쓸모 있는 것**
- **Dead click 감지** — 과거 `.h-center` 투명 오버레이가 클릭을 삼킨 사고와 같은 유형을 자동으로 잡아준다. 정기적으로 확인할 것
- **Rage click** — 반응 없는 요소를 연타하는 지점
- 개별 세션에서 **어느 장면에서 이탈하는지** (평균 참여 7초의 실체 파악)
- `kakao_click`이 0인 이유 — 버튼에 도달은 하는지, 보고도 안 누르는지

**설정 주의**
- 세션 리플레이는 화면을 그대로 기록한다. Masking은 최소 "Balanced" 유지
- 데이터 보관 **30일**. 중요한 발견은 클립으로 저장하거나 이 문서에 적어둘 것
